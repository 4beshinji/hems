# HEMS — Home Environment Management System

**三空間統合型パーソナル AI 基盤**

---

## 一言で言うと

> 実空間・個人電子空間・インターネットを横断的に監視・判断・制御する、
> 完全ローカル動作のパーソナル AI プラットフォーム。

---

## 三空間統合 — HEMS の設計思想

既存のスマートホームは「部屋」しか見ない。AI アシスタントは「会話」しかできない。PC 監視ツールは「マシン」しか知らない。

HEMS はこの 3 つを **1 つの認知エンジンに統合する**。

```
┌────────────────────────────────────────────────────────────────┐
│                                                                │
│   実空間                個人電子空間           インターネット    │
│   Physical Space        Personal Digital       Internet         │
│                                                                │
│   温湿度 / CO2 / VOC    PC CPU/GPU/メモリ      Google Calendar  │
│   気圧 / 照度            プロセス監視           Gmail 未読       │
│   赤外線 (PIR)           ブラウザ状態           GitHub 通知      │
│   24GHz mmWave           ファイルシステム       RSS ニュース     │
│   カメラ (YOLO+VLM)      スクリーンタイム       天気予報 (JMA)   │
│   スマートホーム状態      Obsidian vault        OpenWeatherMap   │
│   心拍 / SpO2 / HRV      買い物リスト                           │
│   睡眠 / ストレス / 疲労                                        │
│                                                                │
│         ↓                    ↓                    ↓            │
│   ┌────────────────────────────────────────────────────────┐   │
│   │              MQTT Bus (統合イベントバス)                 │   │
│   └────────────────────────────────────────────────────────┘   │
│                            ↓                                   │
│   ┌────────────────────────────────────────────────────────┐   │
│   │          Brain — 認知エンジン (30秒サイクル)             │   │
│   │                                                        │   │
│   │  LLM 推論 (ReAct)  ←→  ルールエンジン (フォールバック)  │   │
│   │          ↕                                             │   │
│   │  ワールドモデル: 三空間の状態を統合保持                   │   │
│   │          ↕                                             │   │
│   │  33 ツール: 照明制御 / 音声通知 / PC操作 / タスク生成... │   │
│   └────────────────────────────────────────────────────────┘   │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

**1 つのセンサーが 1 つの値を出すのではなく、3 空間のデータが 1 つの判断を形成する。**

## センサースタック — 「お前を見ているぞ」

HEMS の実空間認知は単一センサーに依存しない。複数モダリティを重ねて死角を潰す。

| レイヤー | センサー | 検知対象 | 特性 |
|---------|---------|---------|------|
| 環境 | BME680 (温湿度/気圧/VOC), MH-Z19 (CO2) | 空気質、気圧変動 | 常時・低コスト・高信頼 |
| 赤外線 | PIR センサー | 人体の動き (存在) | 低遅延・省電力・動体のみ |
| ミリ波 | 24GHz mmWave レーダー | 存在 + 微動 (呼吸) | 暗所対応・静止体も検知 |
| 映像 | YOLO v11s-pose | 人数・姿勢・骨格 | リアルタイム・姿勢分類 |
| 映像+言語 | VLM (moondream / minicpm-v) | シーン理解・状況記述 | センサーでは取れない「文脈」 |
| 生体 | スマートバンド (Gadgetbridge) | 心拍/SpO2/睡眠/ストレス/HRV | 身体内部の状態 |

**VLM の役割**: 他のセンサーが「何が起きているか」を数値で伝えるのに対し、VLM は「それがどういう状況か」を言語で補完する。

- PIR + mmWave: 「誰かがソファにいる」
- YOLO: 「1人、臥位」
- **VLM**: 「ソファで横になっている。照明は点いたまま。テレビのリモコンが床に落ちている」

→ Brain の判断材料が「臥位」から「寝落ちの可能性が高い」に変わる。

### 適応的頻度制御

VLM はセンサーと違い推論コストが高い。HEMS は状況に応じて頻度を制御する。

```
通常時:       30分に1回 (軽量モデル: moondream ~1.8B)
人の出入り検知: 1-5分間隔にブースト (重量モデル: minicpm-v ~3B)
無人・安定:    最大2時間間隔に減衰
オンデマンド:   Brain が describe_scene ツールで任意に呼び出し
```

## 既存アプローチとの位置づけ

### vs. ローカル LLM (Ollama / LM Studio)

ローカル LLM は HEMS の **脳の一部** にすぎない。

LLM 単体は聞かれたら答える。HEMS は 30 秒ごとに三空間を走査し、聞かれなくても判断・行動する。LLM に「身体」と「感覚器」と「自律神経」を与えるのが HEMS。

### vs. opencraw / PC 監視ツール

opencraw は HEMS の **デジタル空間ドメインの一部** として組み込まれる。

PC の CPU が 90% という事実だけでは判断できない。「GPU も高負荷 + 室温 28°C + ユーザーの心拍が上昇」という三空間横断の情報があって初めて「エアコンを強める」という判断が成立する。

### vs. AI 秘書 (ChatGPT / Alexa / Google Assistant)

| | クラウド AI 秘書 | HEMS |
|---|---|---|
| データの場所 | クラウド | **完全ローカル** |
| 環境認知 | マイク音声のみ | **三空間のセンサー群** |
| 能動性 | 呼びかけ待ち | **30秒ごとに自律走査** |
| カスタマイズ | プロンプト程度 | **オープン — ルール・ツール・センサーを自由に追加** |
| デバイス制御 | 対応機器のみ | **HA + SwitchBot + MQTT — 何でもつながる** |

## ドメイン横断判断 — デモシナリオ

### シナリオ 1: 三空間の複合判断

```
14:30  [実空間]      CO2 1200ppm, 室温 28°C
       [実空間]      YOLO: 座位を2時間継続
       [電子空間]    GPU 95% (推論中)
       [生体]        心拍 95bpm (通常より高め)

       → Brain (ReAct):
         Thought: CO2高い + 暑い + 長時間座位 + 心拍上昇
                  GPU高負荷で排熱も影響 → 換気 + 冷房強化 + 休憩促進
         Action:  control_climate(mode=cool, temp=25)
                  speak("2時間経過。換気と休憩を推奨します")
```

### シナリオ 2: VLM によるセンサー補完

```
23:45  [実空間]      PIR: 反応なし (静止)
       [実空間]      mmWave: 存在あり (微動=呼吸)
       [実空間]      YOLO: 1人・臥位 (ソファ上)
       [実空間]      VLM: 「横臥状態。照明点灯中。リモコン落下」
       [生体]        心拍 58bpm (低下傾向)

       → Brain: 寝落ちと判断
         Action:  control_light(brightness=0)
                  speak("就寝を検知。消灯します", volume=0.3)
```

### シナリオ 3: インターネット空間との連携

```
07:00  [生体]        睡眠終了を検知 → wake_up イベント
       [インターネット] ニュース要約を取得 (RSS + Ollama)
       [インターネット] 天気: 午後から降雨予測
       [電子空間]    GitHub: PR レビュー 3件

       → イベント自動化:
         1. 天気レポート (降雨アラート)
         2. ニュースブリーフィング
         3. 未読通知サマリー
       → 音声で一括通知
```

## 技術仕様

| 項目 | 詳細 |
|------|------|
| 認知ループ | 30秒サイクル / 最大5イテレーション ReAct |
| フォールバック | GPU高負荷時にルールエンジンへ自動切替 (zero downtime) |
| GPU 協調 | VLM 推論時に Brain LLM を退避、推論完了後に復帰 |
| MQTT 設計 | マイクロサービス間は全て MQTT / サービス単位 ACL |
| データ保持 | 730日 (raw_events + llm_decisions + hourly_aggregates) |
| LLM | OpenAI / Anthropic / Ollama (3プロバイダー) |
| TTS | espeak / VOICEVOX / Edge TTS / VoiSona Talk (4バックエンド) |

### 段階的導入

```bash
# 最小構成 — 5分で起動
cp env.example .env && cd infra && docker compose up -d --build

# ローカル LLM 追加
docker compose --profile ollama up -d --build

# スマートホーム + 生体 + カメラ + ニュース
docker compose --profile ha --profile biometric \
  --profile perception --profile news --profile ollama up -d --build
```

18 サービス、33 ツール。使うものだけプロファイルで有効化。
