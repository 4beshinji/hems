# W4.6 設計ノート — PostgreSQL 既定化の zero-config UX

対象: [`PLAN.md`](PLAN.md) W4.5' のフォローアップ。2026-06-11 ユーザー決定により PostgreSQL を既定 DB に昇格したが、zero-config 初期体験が失われているため、`make quickstart` / `infra/scripts/install.sh` 等で自動設定を行う。

---

## 1. 現状の問題

### 1.1 W4.5' 実装後の状態

- `env.example` の `DATABASE_URL` は PostgreSQL を指すようになった
- `POSTGRES_PASSWORD=CHANGE_ME_BEFORE_USE` が default
- `infra/docker-compose.yml` の `postgres` service は profile 不要のコアサービス化
- ユーザーが `cp env.example .env && docker compose up -d --build` だけでは、**既知のデフォルトパスワードで PostgreSQL が起動する**

### 1.2 セキュリティ・UX 影響

| 観点 | 影響 |
|---|---|
| セキュリティ | `POSTGRES_PASSWORD=CHANGE_ME_BEFORE_USE` のまま運用するユーザーが出るリスク |
| UX | 以前の SQLite default は `cp env.example .env` で即起動できた。PG 化により初回セットアップが煩雑に |
| 移行 | 既存 SQLite ユーザーのデータ移行は手動スクリプト `infra/scripts/migrate_sqlite_to_pg.py` の実行が必要 |

---

## 2. 設計目標

1. **zero-config 維持**: 新規ユーザーは `cp env.example .env && docker compose up -d --build` で起動可能
2. **デフォルトパスワード排除**: 初回起動時に安全なパスワードを自動生成
3. **既存 SQLite 移行支援**: データを持つユーザーが簡単に PG へ移行できる
4. **SQLite 温存**: 軽量オプションとして `--profile sqlite-lite` 等で利用可能

---

## 3. 選択肢

### 3.1 選択肢 A: `make quickstart` で env 自動生成（推奨）

```bash
# Makefile
quickstart:
	@if [ ! -f .env ]; then \
		cp env.example .env; \
		python infra/scripts/init_env.py --generate-secrets; \
		echo "Generated .env with random secrets. Review before deploy."; \
	fi
	cd infra && docker compose up -d --build
```

`init_env.py` は `.env` 内の以下を自動生成:
- `POSTGRES_PASSWORD`
- `MQTT_PASS`
- `BACKEND_API_KEY`
- `HEMS_INTERNAL_TOKEN`
- `JWT_SECRET_KEY`（存在すれば）

**長所**:
- 既存 `docker compose` フローと親和性が高い
- 生成後にユーザーが `.env` をレビューできる
- `infra/scripts/install.sh` でも再利用可能

**短所**:
- `.env` を上書きする処理の安全性に注意（既存値は尊重）

### 3.2 選択肢 B: compose secret + entrypoint で動的生成

PostgreSQL コンテナ起動時に `POSTGRES_PASSWORD_FILE` 等を使い、初回のみ secrets から読む。backend/brain も同様に `DATABASE_URL` を動的に構築。

**長所**:
- `.env` に平文パスワードを書かなくて済む

**短所**:
- 構成が複雑化
- backend/brain の `DATABASE_URL` 構築が面倒
- 開発体験が煩雑になる

### 3.3 選択肢 C: SQLite を default に戻し、PG は opt-in

W4.5' の決定を巻き戻し、SQLite を default、PG は `--profile postgres` で提供。

**長所**:
- 最もシンプルな zero-config
- 既存 SQLite ユーザーに影響なし

**短所**:
- 監査で指摘された event_store スケール懸念が再燃
- 将来のマルチ occupant / 配布戦略と整合しにくい
- 2026-06-11 ユーザー決定と矛盾

**結論**: 選択肢 A を採用し、必要に応じて C の SQLite オプションも維持する。

## 4. 推奨設計

### 4.1 `infra/scripts/init_env.py`

```python
#!/usr/bin/env python3
"""Generate secure random values for placeholder secrets in .env."""
import argparse
import re
import secrets
from pathlib import Path

ROOT = Path(__file__).resolve().parents[2]
ENV_EXAMPLE = ROOT / "env.example"
ENV_FILE = ROOT / ".env"

SECRETS = {
    "POSTGRES_PASSWORD": 32,
    "MQTT_PASS": 32,
    "BACKEND_API_KEY": 32,
    "HEMS_INTERNAL_TOKEN": 32,
    "JWT_SECRET_KEY": 32,
}


def generate(length: int) -> str:
    return secrets.token_urlsafe(length)


def init_env(*, only_missing: bool = True, dry_run: bool = False) -> None:
    if not ENV_FILE.exists():
        ENV_FILE.write_text(ENV_EXAMPLE.read_text())

    content = ENV_FILE.read_text()
    changed = False
    for key, length in SECRETS.items():
        pattern = rf"^{re.escape(key)}=.*$"
        current = re.search(pattern, content, re.MULTILINE)
        placeholder = current.group(0) if current else f"{key}="
        is_placeholder = (
            not current
            or current.group(0).split("=", 1)[1].strip() in ("", "CHANGE_ME_BEFORE_USE", "CHANGE_ME")
        )

        if not only_missing or is_placeholder:
            new_line = f"{key}={generate(length)}"
            if current:
                content = re.sub(pattern, new_line, content, flags=re.MULTILINE)
            else:
                content += f"\n{new_line}\n"
            changed = True

    if changed and not dry_run:
        ENV_FILE.write_text(content)

    print(f"{'Would update' if dry_run else 'Updated'} {ENV_FILE}")


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--dry-run", action="store_true")
    parser.add_argument("--force", action="store_true", help="Overwrite existing non-placeholder values")
    args = parser.parse_args()
    init_env(only_missing=not args.force, dry_run=args.dry_run)
```

## 5. 既存 SQLite 移行支援

`infra/scripts/migrate_sqlite_to_pg.py` はすでに存在する。以下を追加:

1. `--check` モード: 移行対象レコード数を表示
2. 自動バックアップ: 実行前に SQLite ファイルを `.bak` コピー
3. dry-run 結果を人間可読なサマリで出力
4. README に移行手順を明記

```bash
# 使用例
python infra/scripts/migrate_sqlite_to_pg.py --sqlite-url sqlite:///data/hems.db --pg-url postgresql://hems:$(cat .env | grep POSTGRES_PASSWORD | cut -d= -f2)@postgres:5432/hems --dry-run
```

## 9. リスク

1. **既存 `.env` 上書き**: `--force` オプションの誤用で既存パスワードが変更される。`only_missing` を default にすることで緩和。
2. **secret の平文保存**: `.env` に平文で保存される。これは本プロジェクトの既存方式と一致しており、 distribution.md でより高度な secret 管理（HashiCorp Vault 等）を検討する段階で対応。
3. **SQLite ユーザー置き去り**: README に明確な移行手順を記載し、移行期間中は SQLite オプションを維持。
4. **CI 影響**: CI は既存 `.env` を使わない。`env.example` の placeholder 値が CI 上で問題にならないよう、テスト時は SQLite または test DB を使う必要がある（既存の pytest fixture で対応済みのはず）。
