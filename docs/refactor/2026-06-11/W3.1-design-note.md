**コンストラクタは全 9 件共通**: `__init__(self, broker, port, user="", password="")`、`mqtt.Client(CallbackAPIVersion.VERSION2)`、`if user: username_pw_set(...)`。属性名のみ差分: 7 件が `self._broker/_port`、biometric が `self.broker/self.port` + `self.connected`。

1. **retain**: ha/switchbot/tapo = 常に True / その他 = 常に False / biometric = 呼び出し側指定。→ デバイス state(retain したい)と event/news(retain したくない)の意味差。

> 注: ensure_ascii の不統一は **既存バグ寄り**。gas/obsidian/weather は日本語を含む payload を `ensure_ascii=True`(デフォルト)で `\uXXXX` エスケープ送信している。統一 API では **既定 `ensure_ascii=False` に寄せる**ことを提案するが、これは挙動変更になるため §6 で「ユーザー判断点」として明示する。

## 2. 調査 2 — lifespan パターン差分

全ブリッジが `@asynccontextmanager async def lifespan(app)` + module-level globals + `_tasks: list[asyncio.Task]` + 終了時 `for t in _tasks: t.cancel()` + `mqtt_pub.disconnect()` という同型骨格。差分:

| bridge | MQTT 接続 | client init / セッション | polling task | 固有処理 |
|---|---|---|---|---|
| weather | `MQTTPublisher(...).connect()` | JMA/OWM 分岐 + `await client.start()` | `poll_current` / `poll_forecast` | provider 分岐・can_poll ガード(`main.py:24-75`) |
| gas | 同上 | `GASClient(...).start()` | calendar/tasks/gmail/sheets/drive ×5 | URL 未設定時の早期 warning(`main.py:23-69`) |
| news | 同上 | `OllamaClient` + fetcher/summarizer/urgency | initial / daily / urgent ×3 | startup `_initial_summary`、`datetime` 由来の daily loop(`main.py:147-184`) |
| tapo | `cfg = config.load_config()` → `MQTTPublisher` | `TapoClient(...)`(start なし) | `_poll_loop` / `_status_loop` | **唯一 dataclass config**、creds 未設定 warning(`main.py:70-99`) |
| switchbot | 同上 | `async with aiohttp.ClientSession()` の中で `start(session)` | `_poll_all_devices` / `_bridge_status_loop` | webhook 登録、**session を lifespan が保持**(`main.py:163-204`) |
| obsidian | 同上 | watchdog watcher | vault watch | — |
| knowledge | 同上 | watcher + index | source watch | — |
| **ha** | 同上 | `async with aiohttp.ClientSession()` 内で `start(session)` | **`ha_client.reconnect_loop(_on_state_changed, _poll_states)`** + status loop | **WebSocket reconnect ループ**(client 側に内包)。fallback polling(`main.py:113-137`) |
| **biometric** | `await send_queue.init()` → `MQTTPublisher(...).connect()` | huami/zepp provider 条件起動 | huami_poll / zepp_poll / status / **`_flush_queue_loop`** | **send queue(SQLite outbox)**。`_mqtt_publish` ラッパ経由で失敗時 enqueue、`mqtt_pub.connected` を見て flush(`main.py:194-413`, `send_queue.py`) |

**固有処理は 2 件のみ厚い**:
- **ha**: WebSocket reconnect は `ha_client.py` 内に既に閉じている。lifespan からは `reconnect_loop(...)` を 1 タスク登録するだけ。→ `_common` の lifespan ヘルパーは「task factory のリストを受け取って `create_task` + cancel する」形にすれば ha も素直に乗る。MQTTPublisher 自体は retain=True 派なので移行は単純。
- **biometric**: send queue が MQTTPublisher の `connected` / `publish() -> bool` に依存。`_mqtt_publish` ラッパ(`main.py:203`)が「publish 成功なら return、失敗なら `send_queue.enqueue`」、`_flush_queue_loop` が `mqtt_pub.connected` を見る(`main.py:326`)。→ **統一 API はこの 2 つ(`connected` プロパティ・`publish` の bool 戻り)を必ず保持する必要がある**。

## 4. 調査 4・5 — 既存共有基盤 / 配置・import 方式

### 4.1 既存基盤の有無
- **`infra/base/`** に `hems-base:py3.11` イメージあり。9 ブリッジ全部が `FROM hems-base:py3.11`(各 `Dockerfile` 確認済み)。共通 deps(paho-mqtt / fastapi / loguru / python-dotenv 等)はここで pre-install(`infra/base/requirements.txt`)。
- 共通 import 可能な Python パッケージは **現状存在しない**。各ブリッジは `src/` 直下の flat module(`config.py` / `mqtt_publisher.py` / `main.py`)を相対 import なしで参照(`from mqtt_publisher import MQTTPublisher`)。
- **import の致命的制約(コンテナ)**: `infra/docker-compose.yml` は各ブリッジに **`../services/<bridge>/src:/app` のみ bind mount**(例 `:303`, `:340`, `:397`, ...)。`services/_common/` はマウントされないため、**ソース bind だけでは `_common` がコンテナ内から見えない**。

### 4.2 `_common` の配置・import 方式(結論)

採用案: **`infra/base` イメージに `_common` を同梱**(PLAN の「hems-base イメージに同梱」に一致)。

```
services/_common/
  hems_common/                 # import 名(衝突回避のため flat 名 'config' 等は使わない)
    __init__.py
    mqtt.py                    # MqttPublisher
    config.py                  # BridgeConfig + load helpers
    lifespan.py                # build_bridge_lifespan / task factory ヘルパー
    auth.py                    # verify_internal_token
    status.py                  # publish_bridge_status
  pyproject.toml               # name=hems-common, パッケージは hems_common
```

import は `from hems_common.mqtt import MqttPublisher`(flat な `mqtt_publisher` ではなく **名前空間付き**にして、テストの `sys.path.insert(src)` による衝突を避ける)。

**配布(ビルド)**: `infra/base/Dockerfile` に追記:
```dockerfile
COPY _common /tmp/_common         # build context を infra/ → repo root に変える必要あり(§4.4)
RUN pip install /tmp/_common
```
→ pip install すると site-packages に入り、bind mount に依存せず全ブリッジコンテナで import 可。

**ローカルテストでの import**: `tests/conftest.py` に `sys.path.insert(0, str(_root / "services" / "_common"))` を 1 行追加(`conftest.py:13-16` の隣)。これで pytest からも `hems_common` を import でき、コンテナと同じ import 文が通る。pip install -e でも可だが conftest の 1 行が最も摩擦が低い。

### 4.3 build context 問題(要注意)
現状 `base` の build context は `./base`(`docker-compose.yml:10-11`)。`_common` を COPY するには context を **repo root or `services/` を含む位置**に広げる必要がある:
```yaml
base:
  build:
    context: ..              # infra/ から見て repo root
    dockerfile: infra/base/Dockerfile
```
→ Dockerfile 内の `COPY requirements.txt` は `COPY infra/base/requirements.txt` に、`COPY _common` は `COPY services/_common` に変わる。**これは W3.1 で必要な唯一の Dockerfile/compose 変更**。9 ブリッジ個別の Dockerfile は変更不要(`FROM hems-base` のまま `_common` を継承)。

### 4.4 stt `_check_auth` の参照形(verify_internal_token)
実装(`services/stt/src/main.py:56-61`):
```python
def _check_auth(authorization: str | None):
    if not _INTERNAL_TOKEN:        # 未設定 = dev mode、認証スキップ
        return
    token = (authorization or "").removeprefix("Bearer ").strip()
    if not hmac.compare_digest(token, _INTERNAL_TOKEN):
        raise HTTPException(status_code=401, detail="Unauthorized")
```
これを `hems_common.auth.verify_internal_token` として一般化(token を引数化 or env 読取を内包)。`hmac.compare_digest` による定数時間比較・未設定時 dev スキップを保存。S3(ブリッジ HTTP への token 横展開)はこの関数を各ブリッジの REST 経路に差し込むだけで一括解消。

## 5. 統一 API シグネチャ案

### 5.1 `MqttPublisher`(`hems_common/mqtt.py`)
9 ブリッジ全差分を吸収する設計。**コンストラクタで方針を固定、publish で個別上書き可能**:

```python
class MqttPublisher:
    def __init__(
        self,
        broker: str,
        port: int = 1883,
        user: str = "",
        password: str = "",
        *,
        client_id: str = "",
        default_retain: bool = False,     # ha/switchbot/tapo は True を渡す
        default_qos: int = 0,
        ensure_ascii: bool = False,       # 既定で日本語をそのまま(§6 判断点)
        error_level: str = "error",       # "error" | "debug"
        raise_on_connect_error: bool = False,
        track_connection: bool = True,    # on_connect/disconnect + connected
        auto_reconnect: bool = True,      # reconnect_delay_set(1, 60)
    ): ...

    @property
    def connected(self) -> bool: ...      # biometric send queue が依存

    def connect(self) -> None: ...        # raise_on_connect_error で挙動切替

    def publish(
        self,
        topic: str,
        payload: dict,
        *,
        retain: bool | None = None,       # None → default_retain
        qos: int | None = None,
    ) -> bool: ...                        # rc==SUCCESS を返す(biometric が依存)

    def disconnect(self) -> None: ...
```

各ブリッジは生成時に方針を渡すだけ:
- ha/switchbot/tapo: `MqttPublisher(..., default_retain=True, error_level="error")`
- gas/obsidian/weather: `MqttPublisher(..., default_retain=False, error_level="debug", raise_on_connect_error=True)`
- news/knowledge: 上に加え `ensure_ascii=False`(現状維持)
- biometric: `MqttPublisher(..., track_connection=True, auto_reconnect=True)` + `publish(topic, data, retain=...)`

> **後方互換の肝**: 既存テスト `test_ha_bridge.py:TestMQTTPublisher.test_publish` は `MQTTPublisher("localhost", 1883)` を **positional** で生成し `pub.client` を MagicMock に差し替えて `pub.client.publish.assert_called_once()` を検証する(`tests/test_ha_bridge.py:155-160`)。統一 API も **`broker, port` を positional 受け・内部に `self.client` を持つ** こと。ha は移行順最後(8 番目)なのでこのテストは ha 移行 commit で API に追従させる。
> biometric テストは module-level `_mqtt_publish` を patch するだけで MQTTPublisher 内部に触れない(`test_biometric_steps_dedupe.py:44,70` の `def fake_publish(topic, data, retain=True)`)。→ `_mqtt_publish` ラッパの **`retain=True` 既定とシグネチャ**を保てば緑のまま。

### 5.2 lifespan ヘルパー(`hems_common/lifespan.py`)
固有処理を hook で差し込む。task は **factory(引数なし coroutine を返す callable)のリスト**で受ける(ha の `reconnect_loop` も biometric の flush loop もこの形に乗る):

```python
@asynccontextmanager
async def bridge_lifespan(
    app, *,
    mqtt: MqttPublisher,
    on_startup: Callable[[], Awaitable[None]] | None = None,   # client init, session, send_queue.init 等
    task_factories: list[Callable[[], Awaitable]] = (),         # 各 polling loop
    on_shutdown: Callable[[], Awaitable[None]] | None = None,   # client.stop, send_queue.close 等
):
    mqtt.connect()
    if on_startup: await on_startup()
    tasks = [asyncio.create_task(f()) for f in task_factories]
    try:
        yield
    finally:
        for t in tasks: t.cancel()
        if on_shutdown: await on_shutdown()
        mqtt.disconnect()
```

`async with aiohttp.ClientSession()`(switchbot/ha)や send_queue は `on_startup`/`on_shutdown` クロージャに閉じ込める。これで lifespan 骨格(~40 行 ×9)を共通化。**強制はしない** — 移行で困るブリッジは独自 lifespan のまま `MqttPublisher` だけ使ってよい(W3.2 を 1 件ずつ安全に進めるため)。

### 5.3 `BridgeConfig`(`hems_common/config.py`)
tapo 方式を一般化。MQTT 共通フィールド + JSON env loader を提供:

```python
@dataclass
class MqttConfig:
    broker: str = "mosquitto"
    port: int = 1883
    user: str = ""
    password: str = ""

def load_mqtt_config(*, default_user: str = "") -> MqttConfig: ...
def load_json_env(key: str, default: str = "{}") -> dict: ...   # tapo の _load_json_env を昇格
```
各ブリッジは自分の dataclass に `mqtt: MqttConfig` を持たせる。os.getenv 派 8 件は移行時、モジュール定数 export(`MQTT_BROKER = ...`)を **残したまま**内部で `load_mqtt_config()` を使い、段階的に dataclass へ寄せる(挙動不変優先)。

## 9. リスク・落とし穴

1. **import path 衝突(最大リスク)**: 各ブリッジは flat module(`config`, `mqtt_publisher`)を相対 import なしで使い、テストは `sys.path.insert(src)` する。`_common` を flat 名(`config.py`)で作ると衝突する。→ **`hems_common` 名前空間必須**。`conftest.py:15-16` が gas-bridge の config shadow を警告している通り、この罠は既知。
2. **Docker bind mount で `_common` が見えない**: §4.1。pip install(イメージ同梱)で解決。bind mount に頼らない。
3. **build context 拡張の副作用**: context を repo root に広げると `.dockerignore` がないとビルドコンテキストが肥大化。→ `infra/base/.dockerignore` 相当(repo root の `.dockerignore`)で `services/*/node_modules`・`.venv`・`__pycache__` を除外する必要。要確認。
4. **循環依存**: `hems_common` は paho-mqtt/loguru/fastapi のみに依存し、ブリッジ固有モジュールを import しないこと(逆向き依存のみ)。
5. **テストの前提**: ha の `test_publish` は positional 生成 + `.client` 属性に依存。biometric は `connected`/bool 戻りに依存。この 2 契約を統一 API が破ると移行で赤化。§5.1 で保護済み。
6. **ensure_ascii 統一**: gas/obsidian/weather を `ensure_ascii=False` に寄せると MQTT 上の payload バイト列が変わる(`晴` → `晴`)。consumer(brain world_model)は `json.loads` するので **意味は不変**だが、retained payload の見た目が変わる。挙動「不変」を厳密に取るなら weather/gas/obsidian は現状の `True` を明示的に渡して維持し、ensure_ascii の正規化は別 row に切る判断もある(§6 ユーザー判断点)。

## 10. 実装 GO 前にユーザー判断が要る点

1. **ensure_ascii の統一方針**: 全ブリッジ `ensure_ascii=False`(日本語をそのまま、推奨・consumer 影響なし)に寄せるか / 各ブリッジ現状維持(挙動完全不変優先)か。前者は retained payload の見た目が変わる(意味は不変)。
2. **base build context の拡張可否**: `infra/base` の context を repo root へ広げ、`.dockerignore` を整備することへの同意。これが `_common` 同梱の前提。代替(各ブリッジへ `_common` を bind mount + PYTHONPATH)も可だが 9 compose entry の編集が増え PLAN の「Dockerfile 変更不要」と整合しにくい。
3. **config dataclass 化の深さ**: W3.2 で os.getenv 派 8 件を「定数 export 維持(浅い移行・低リスク)」に留めるか、「dataclass へ全面移行(深い・コード変更大)」か。本ノートは前者を推奨(挙動不変・1 commit を軽く保つ)。
4. **ha status topic 改名のタイミング**: `hems/home/bridge/status` → `hems/ha/bridge/status` は W3.3 で brain 併読つきで行う前提。W3.1/W3.2 では topic を触らない(移行を retain/error 方針のみに限定)で良いかの確認。
