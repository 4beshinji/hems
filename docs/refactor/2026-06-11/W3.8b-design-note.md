# W3.8b 設計ノート — edge ファーム `office/*` → `hems/sensors/*` topic 変更

対象: `edge/` 配下の MicroPython/ESP32 ファームウェアと、mosquitto ACL。
出典: [`PLAN.md`](PLAN.md) W3.8b。
依存: W3.8a(brain が `office/*` と `hems/sensors/*` を併読済み)。
制約: **本ノートは調査 + 設計のみ。コード変更は次セッション。**

---

## 1. 目的

物理センサの MQTT topic prefix を SOMS 遺産の `office/{zone}/{device_type}/{device_id}/{channel}` から
HEMS canonical の `hems/sensors/{zone}/{device_type}/{device_id}/{channel}` へ段階移行する。

W3.8b は **コード変更フェーズ**。実機へのファーム書き込み(flash)と疎通確認はユーザー作業。

## 3. 設計判断

### 3.1 `topic_prefix` default 変更のみで十分か？

**結論: はい。** `edge/lib/soms_mcp.py` の default を変更すれば、`edge/office/*/main.py` は自動的に新 prefix を使う。
config.json で `topic_prefix` を明示上書きしている既存デバイスは影響を受けない(意図通り)。

### 3.2 Perception service は ACL 変更で対応可能か？

`hems-perception` user は perception コンテナがカメラ/activity データを publish するために使用。
新 canonical へ移行するには `hems/sensors/#` への write 権限が必要。
brain は既に W3.8a で `hems/sensors/*` を subscribe しているので、受信側変更は不要。

### 3.3 `hems-iot` user への権限追加

edge ファーム(MCP デバイス)は `hems-iot` shared credential を使用。新 prefix への publish を許可するため、
`hems/sensors/#` write を追加する。

### 3.4 `device_type` の扱い

新 canonical: `hems/sensors/{zone}/{device_type}/{device_id}/{channel}`

- `edge/lib/soms_mcp.py` の default は `sensor` device_type 固定。
- `edge/lib/swarm/hub.py` も `sensor` 固定。
- `edge/test-edge/camera-node` は `camera` device_type を使用。
- perception のカメラ/activity 出力は perception 側で `camera` / `activity` device_type を使う。

`device_type` の命名は現状の `sensor` / `camera` / `activity` を維持する。
